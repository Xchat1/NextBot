# NextBot P1 工程交付与验收计划

**v0.1 工程设计稿 · 2026-11-27 · 拟用于内部试用评审**

P1 的交付是一条可以在真机上走通的路径。所有者在自己的主机认领实例，从电脑提交一个修复任务，关掉页面，再用手机处理问题、授权一次实际测试、核对差异和测试证据，接受指定版本。单节点只允许一个写执行。P1 由 Codex 执行、所有者直接验收。P2 再引入独立复核。本稿列出后续工程工作及其通过条件，所有场景均待实现和实测。

设计依据见[系统架构](01-architecture.md)、[API 与协议](02-api-protocol.md)、[数据与恢复](03-data-recovery.md)及[产品功能规格与验收](../product/03-functional-spec.md)。下文沿用产品用例编号。工程工作包可以拆成工单，用例编号在拆分后保持稳定。

第一步在 Apple Silicon Mac 上验收桌面应用。打开应用后能够完成本机设备绑定、仓库登记、Codex 文件执行、查看差异和人工验收。桌面应用通过后再验证手机接手。云端部署后续单独验收。下文的 Linux 用例继续用于受管容器测试及跨端联调。

## 1. 首轮可行性验证

首先在一台可重置的 Linux x86_64 主机上记录发行版、内核、Git、Codex CLI 版本、本地 app-server 的 stdio 协议版本、已启用工具及执行配置。以新建的演示仓库和专用模型登录进行以下验证。每项必须保存真实节点的观测结果。前端演示、假适配器和 Agent 对自身权限的描述都不足以确认运行能力。

| 门槛 | 验证动作 | 工程决定 |
| --- | --- | --- |
| G1 文件编辑能独立工作 | 让真实 Codex 读取演示项目、修改导出逻辑并新增一份测试文件。执行环境只开放任务工作树内所需的读和定向文件写入。核对最终差异、暴露的工具、节点进程记录和 Agent 身份可见的资源。再要求它用普通终端运行演示测试，核对拒绝记录及实际启动次数为零。 | 只有在禁用任意 Shell、命令执行与其他可启动程序的工具后仍能完成编辑，才能登记为可写执行配置。核对文件接口保护 Git 管理区、节点日志和控制库，并记录模型登录进程可读取的凭据范围。 |
| G2 测试仅由 Runner 的受管执行器启动 | 所有者预登记一个测试项，由可信启动器按固定程序及参数，在受限的独立环境中读取已固定的待测输入。Agent 只提交测试请求。分开演练允许、拒绝、超时、输入内容改变。核对节点侧实际启动记录。确认 Agent 环境不能接触启动器的控制通道，测试环境只得到完成测试所需输入。 | 允许时一次，拒绝、超时和指纹不符时均为零。审批请求绑定不可变输入快照，测试执行器启动时再次核对参数和输入摘要。无法证明这一点的配置标为不支持受管测试。 |
| G3 生命周期能由节点核实 | 记录一次真实启动、提问答复、正常退出、取消、非预期退出。检查哪些回执能关联尝试、哪些原生会话能续接，以及进程结束的独立证据。关闭桌面页面观察节点上的执行。 | 支持矩阵分开标注启动、取消、提问、文件编辑、受管测试和原生续接。原生续接可以标记为不支持，须能走 A17 的新尝试路径。无法核实进程停止时，写名额保持占用。 |

三个门槛形成按“平台、CLI 版本、启动配置”区分的结论。G1 或 G2 未通过，则该配置不得承接本期演示任务，P1 的 A11 保持未通过。先换受控配置重新验证，或回产品评审调整承诺。不得以授权弹窗替代节点执行证据。Linux x86_64 是首选验证环境，macOS arm64 是候选环境。只有在相同门槛与对应验收用例上取证后，才能在支持清单中公布该组合。

## 2. 工作包、负责人及依赖

负责人是签收职责，一个人可以承担多个角色。按退出条件排期，待门槛结果和可用人力确定后再承诺日历日期。W0 最先启动。任务、命令、事件和设备的公共契约一旦冻结，W1 的持久化与 W5 的界面工作可独立推进。W2 的单机部署、W3 的归档设计也可并行。若 W0 失败，仅阻止相关配置接入真实执行或受管测试、对应范围的验收及 P1 试用放行。W4 接真实 CLI 前须复验通过，W6、W7 再分别联调和签收。

| 工作包 | 负责人角色 | 前置依赖 | 可交付成果与退出条件 |
| --- | --- | --- | --- |
| W0 执行能力验证 | Runner 负责人，测试负责人复核 | 测试主机、专用账号、演示仓库 | 完成 G1–G3，留存版本、配置、真实差异、权限及进程观测、每项能力的通过条件和结论。选择一套能满足 P1 的组合。 |
| W1 任务、命令和事件持久化 | Control 负责人 | 任务、命令和事件公共契约已冻结 | Go Control 维护 SQLite WAL 数据库、事务中的命令和有序事件、命令去重与唯一写名额。能从一次 REST 提交追到领取、决定和终态。SSE 可按位置补读，位置失效可切换快照。 |
| W2 安装、所有者和设备 | 部署与身份负责人 | 已选定的 Linux 验证主机 | 一套 Go 可执行文件以 Control、Runner 两个角色在同机分进程启动。Web 使用私网 HTTPS。Runner 主动通过受限 Unix 域套接字领取命令和上报，浏览器无节点直连入口。交付数据目录与权限说明、本机首次认领、单次手机配对、撤权及会话失效流程。 |
| W3 工作区、归档和备份清单 | 存储与工作区负责人 | W0 固定输入的约束 | 从固定提交创建独立工作树，归档差异、清单及测试记录。产物不可变，索引已发布时内容可读且校验一致。提供 SQLite 一致性备份及其引用的产物集合。清单列出来源、文件数、摘要及排除项。 |
| W4 真实派发、授权、恢复 | Runner 负责人 | W0、W1、W2、W3 | 完成真实 Codex 文件编辑、问题答复、测试执行器、取消、节点重连和结果核对。派发回执与实际执行结果分别持久化。无回执时能保留原尝试及待核对状态。 |
| W5 桌面与手机任务页 | Web 负责人 | W1 的 REST/SSE 契约、W2 的设备流程 | React + TypeScript 响应式页面覆盖建单、待办、授权、按版本读证据、验收、重连与过期指引。在窄屏实机上可从待办完成决定，并在另一设备看到同一结果。 |
| W6 单机双端联调 | 测试负责人，Control、Runner、Web 各签收其证据 | W1–W5 | 在隔离测试实例执行第 4 节所有 P1 场景。每项有可重现步骤和可定位的原始记录。失败项修复后用新执行编号重测。 |
| W7 干净环境安装与试用评审 | 自托管维护者，产品负责人签收 | W6 | 操作者仅依安装说明从未认领实例完成正常交付，再演练一次断连与恢复。核实支持清单、数据落点、已知限制、未决缺陷，按第 5 节判断能否进入内部试用。 |

## 3. 测试环境、夹具与取证

- **主机与网络。** 使用一台 Linux x86_64 测试主机、一个受信的私网 HTTPS 地址、一个桌面浏览器、一部运行 Safari 的真实 iPhone 及一个独立浏览器配置供失效配对测试。记录系统、浏览器和 CLI 的实际版本。手机经同一私网或已有 VPN 访问，证书受两端信任。不依赖 NextBot 厂商账号或公共中继。模型账号、供应商网络分别准备。每次普通掉线、暂停进程或停止服务试验只作用于专用实例。
- **演示仓库。** 从同一个干净提交创建测试样例。普通输入可正常导出，空数据触发缺陷。准备既有导出格式的对照样本。所有者登记一个可实际运行的测试项，保留预期结果和固定启动器身份。每个用例取单独的任务、工作树和诊断标记。测试输入、Git 基准和预期结果可复用。
- **节点证据。** 记录命令标识、任务与尝试标识、产物版本及摘要、事件位置、决定设备、节点实际启动及退出记录。为受管测试增加测试进程自己的无敏感标记，与执行器记录相互核对。对“零次启动”的情形先用正常授权作正对照，再覆盖所测时间段核对两处记录。标注哪些证据来自真实 CLI、哪些来自辅助夹具。
- **数据与故障条件。** 为断线、回执延迟和短历史保留准备可重复的测试配置，允许临时断开网络、暂停进程或重启服务。每次只改变所列条件。测试人员应能复原条件，使用节点记录区分“浏览器未收到答复”“节点失联”“节点已连通但结果未知”。仅采集演示数据。证据中不含配对凭据、真实密钥及完整供应商会话。

## 4. P1 逐项验收

下表 15 项分别对应产品规格中首次要求 P1 通过的用例。“证据”指测试执行时必须留存的材料，不能单凭任务页面的状态判定运行结果。

### 安装、身份与执行

| 用例及工作包 | 准备与操作 | 通过标准 | 留存证据 |
| --- | --- | --- | --- |
| A01 私网、持久化与备份 · W1/W2/W3 | 从未认领实例开始，先在私网浏览器尝试自行认领，再由主机管理员发起首次绑定。核对入口已关闭，连接手机，完成并归档导出任务。正常重启服务，重新打开任务，生成备份，逐文件校验。 | 远端陌生设备不能抢先认领。只产生一个所有者。两端经私网 HTTPS 访问，无公共中继。重启后原历史和差异可读，备份中实际对象的个数、摘要均与清单相符。 | 认领审计、访问拓扑、重启前后任务及产物标识、归档摘要、备份清单和独立校验报告。 |
| A02 配对与撤权 · W2/W5 | 可信桌面签发配对请求，手机兑换。用独立浏览器重用已消费凭据，再试一份已到期凭据。保持手机事件流打开，桌面撤权后触发新事件，用手机重新读取和提交决定。 | 重用和过期均失败。撤权后旧连接不再收到新数据，新读写请求受拒。桌面仍能访问，撤权审计可定位设备。 | 配对与撤权时间、设备标识、事件流停止位置、拒绝回执及桌面审计。 |
| A03 节点能力与登录 · W0/W2/W4 | 用已登录、通过 G1–G3 的 Codex 配置派一单。分别换到未登录测试配置、缺少必需能力的配置再提交同类任务。 | 第一单被节点实际领取并启动。后两单均不启动 CLI，任务页能区分登录问题与具体能力缺项。 | 三份配置摘要、节点能力和领取记录、实际进程启动记录、任务页原因。 |
| A05 工作树隔离 · W3/W4 | 从同一基准创建两个任务。先在第一个任务工作树中新建标记文件并归档一项证据，再取消。在第二个任务取得名额后检查其工作树及原目录。 | 两个工作目录和归属清晰。标记文件只在第一个工作树出现。取消后的已归档证据仍可读。 | 两个任务的基准、工作树路径、三处文件清单、取消记录和归档校验值。 |
| A06 排队、重发和取消 · W1/W4/W5 | 连续提交 A、B 两个任务，使 A 保持运行。手机通过自己的设备会话，携带桌面提交 B 时相同的命令标识和相同请求内容再次提交。服务端先独立验证两台设备的身份，再按同一所有者的命令标识查重。观察队列，取消 B，再让 A 结束。 | 总计两个任务。B 排队期间无执行进程，取消后不再领取。A 退出且完成归档后释放名额。 | 两台设备各自的鉴权记录、同一命令标识与结果、任务数、队列及名额变更、节点启动记录。 |
| A07 掉线、进程与原生会话 · W0/W4/W5 | 在运行中关闭页面再重连，记录原尝试。另一次用例在正常生命周期中停止测试 CLI，分别核对能确认的会话和无法确认的执行结果。 | 只关页面时同一尝试仍在运行。确认可原生续接时展示其入口。配置不支持时标出限制并转 A17。结果不明时阻塞并保留原尝试，核实进程与产物前不重派。 | 前后尝试标识、会话引用或不支持记录、节点进程状态、归档与界面显示的恢复选项。 |

## 5. 证据签收与阶段退出

每次执行建立一份证据索引，写明用例、工作包、构建及平台组合、配置摘要、准备步骤、预期与实际、任务／尝试／版本和原始证据位置。用例负责人署名并记录日期。W6 测试负责人对照独立节点证据复核，W7 由产品负责人在同一索引上给出“进入内部试用”或“退回修订”及理由。复测在同一缺陷下追加执行记录，保留原失败证据。涉及设备或凭据的材料先脱敏再入索引。

**P1 退出条件。** 在至少一个明确标注的平台与版本组合上，G1–G3 有结论且满足必需能力，15 条 P1 用例全部通过，干净安装的所有者能走通桌面派单到手机验收。受管测试未经授权仍能运行、结果未知时被自动重放、错误版本被接受、陌生设备抢先成为所有者，任一出现均退回对应工作包。安装或演练耗时可记录为下一阶段估算依据。

**P2 保留用例。** A04、A08、A10、A14 验证第二种 CLI、强制只读的独立复核、版本门控和可脱敏追溯的最终决定。A18–A23 验证复核迟到、返工上限、旧版决定、干净实例恢复、无效备份及双端授权竞争。A25–A27、A29 验证设备全部丢失、人工改动保护、归档损坏或证据缺失、Control 重启而原执行仍在。P2 以“Codex 执行、Claude Code 强制只读复核”为必测方向，反向组合须单独通过后开放。面向真实用户的首次部署计时、手机验收样本量及并发决定轮数沿用产品首发门槛，进入 P2 发布评审时再签收。
