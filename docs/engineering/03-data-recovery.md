# NextBot 数据模型、持久化与恢复

**v0.1 工程设计稿 · 2026-11-27 · P1 内部验证，P2 首发**

本设计说明一次操作写在哪里、何时可向客户端确认，以及进程退出后依据什么继续。[功能规格与验收](../product/03-functional-spec.md)定义业务规则，[API 与事件协议](02-api-protocol.md)定义浏览器和 Runner 的通信契约。

## 1. 数据所有权

| 写入者 | 持有的数据 | 成功的含义 |
| --- | --- | --- |
| Go 控制服务 | 本机磁盘上的 SQLite 主库及不可变产物目录。保存任务、决定、队列、待办、审计、同步事件和产物引用。 | 业务决定与相应派发意图在数据库内同时提交，才向调用方返回成功。动作的真实完成时间以后续回执为准。 |
| 独立 Go Runner | 同机 Unix socket 主动领取命令、本地工作树、Agent 原生会话及独立的持久执行日志。模型登录凭据由本机适配器使用。 | 先持久记录即将启动的命令，再执行，取得结果后先写本地回执，再上报。控制服务确认收妥前持续保留可重传的回执。 |
| 桌面和手机 Web | 共用 REST 读写和 SSE 订阅。可保存最近同步位置和视图缓存。 | 决定以服务端命令回执为准。设备重连后重新确认当前状态及待办。 |

只有控制服务打开主库和产物目录。SQLite 采用 WAL、外键约束与短写事务，关键决定使用 FULL 同步级别。数据库、WAL 与共享内存文件置于同一受支持的本机文件系统。监控写等待、WAL 大小和未结束的读事务，慢速客户端下载由产物文件单独承担。Runner 只能通过 socket 上报或传送产物，凭操作系统账户与 socket 权限隔离控制库、节点日志和 Agent 子进程。单机部署不要求两个进程共享写权限。[SQLite WAL](https://sqlite.org/wal.html) · [SQLite 持久化设置](https://sqlite.org/pragma.html#pragma_synchronous)

## 2. 持久对象、约束与读取路径

下表给出逻辑记录和字段名，供建模与评审。标识不复用。JSON 使用 lowerCamelCase。`revision` 是任务业务版本，`seq` 是全实例提交的事件序号，两者独立。数据库按整数排序，在线上以十进制字符串传输，`expectedRevision`、`afterSeq`、`highWater` 同样处理。时间用服务端 UTC，Runner 观测时间另存，显示时转换为用户时区。关联历史默认禁止级联删除。

| 记录 | 核心字段和约束 | 必要索引或主要读取路径 |
| --- | --- | --- |
| 实例、所有者、设备、配对与会话 | `instanceId`、`streamId`、`highWater`、`ownerId`、`authEpoch`。每设备独立 `deviceId`、绑定与撤销时间。配对凭据、会话仅持有不可逆校验材料、到期和已用时间。 | 每实例一个所有者。令牌校验值唯一，按设备及有效状态查会话。审计引用设备历史，撤权立即阻止读写和 SSE。 |
| 节点、能力与工作区 | `nodeId`、实例绑定代次、适配器版本、能力与验证时间。`projectId` 对应登记的节点仓库。`workspaceId` 对应任务、节点、受管路径和 `baseCommit`。 | 节点及适配器组合查能力。节点内当前工作区路径唯一。基准固定为已存在的 Git 提交。工作区按任务和历次尝试查找。 |
| 任务、阻塞与写名额 | `taskId`、`projectId`、目标与验收条件、主状态、`revision`、`currentAttemptId`、`currentArtifactVersionId`、返工轮数、来源任务。独立阻塞持有来源标识、创建和解除时间。 | 按项目、主状态和入队顺序查询。一个节点最多一条有效写名额，唯一指向当前写尝试。相同阻塞来源只有一条有效记录。 |
| 执行或复核尝试 | `attemptId`、`taskId`、任务内序号、角色、`nodeId`、适配器、受管环境、输入工作区或产物、原生会话标识、开始和结束时间、实际终止原因和写名额代次。 | 任务和尝试序号组合唯一。以任务与角色展开历史。当前尝试指针必须指向同一任务。进程身份另记启动时间及实例随机标识，避免 PID 重用误认。 |
| 命令回执及派发队列 | 用户命令记录 `ownerId`、发起 `deviceId`、`Idempotency-Key`、规范化请求摘要、首次响应和目标标识。内部 `commandId` 对应尝试、Runner、写名额代次、动作及载荷摘要、领取和确认进度。每次领取持有 `connectionId`、`generation`、`leaseId` 和到期时间。`reportId` 标识一条不可变回执。 | 浏览器业务命令以 `ownerId` 和 `Idempotency-Key` 组合唯一。同一所有者的两台设备可重发同一命令。待派发按节点、状态和排队顺序查。内部命令标识唯一，Runner 重传沿用原 `reportId`，重复上报仅返回既有确认。 |
| 授权、提问及决定 | `requestId` 关联尝试及类型，记录到期、目标、动作与输入指纹或问题内容。决定记录请求、设备、时间及允许、拒绝或答复结果。验收决定关联任务、待办和产物版本。 | 每项待办只允许一个生效决定。按所有者及未解决状态列待办。请求与决定必须同任务、同尝试，验收另核对待验版本。 |
| 产物、证据、复核 | `artifactVersionId`、`taskId`、产出尝试、任务内版本、基准、清单摘要。证据项含类型、内容摘要、字节数及归档引用。复核记录绑定复核尝试、输入版本、结论、理由和证据引用。 | 任务内版本唯一。按摘要查内容，按尝试与版本查产物。复核记录只能引用本次输入的版本与证据。晚到报告仅追加到原尝试历史。 |
| 审计、同步事件及版本元数据 | 审计持有操作者或节点、命令、任务、决定、对象、来源时间与提交时间。同步事件持有 `streamId`、`seq`、事件类型、对象标识及必要视图变更。另存数据结构与归档格式版本。 | 事件按全实例 `seq` 顺序读取。审计按任务、命令、请求和时间检索。数据库记录当前 `highWater`，清理事件不回拨。 |

Runner 本地日志按控制实例及其绑定代次、`commandId` 唯一登记执行。记录 `attemptId`、写名额代次、领取代际和租约、载荷摘要、是否已经进入启动窗口、可验证的进程身份、结果和待确认的 `reportId`。Runner 重启恢复日志后才领取新命令。Agent 原始输出单独限额保存，授权及执行回执不依赖终端文本解析。

## 3. 事务边界和并发决定

1. **接收用户命令。** 先校验设备当前身份和访问权，再按 `ownerId` 和 `Idempotency-Key` 查回执。键和规范化请求摘要都相同则返回原业务结果，即使换了设备或当前 `revision` 已变化。回执保留最初生效决定的设备，重传设备不能改写。可跨设备回读的回执只含业务结果和引用。配对秘密、会话材料等高敏内容不进入该回执缓存。键相同而载荷、目标或前置版本不同时拒绝复用。首次请求按协议的冲突优先级，在同一短事务先查已决、过期或关闭的待办，再核对 `expectedRevision`、任务、当前尝试及目标版本。草稿创建尚无既有任务版本，按协议使用创建命令的幂等键。
2. **提交一项决定。** 插入唯一决定、关闭对应待办和阻塞、更新任务并递增 `revision`，写入审计、同步事件及用户回执。获准且需要执行时，在同一事务加入内部命令。提交后才通知订阅端。另一设备用不同键对同一请求提交相反决定时，返回冲突及已生效结果，不能替换决定。到期与批准也遵守同一规则。节点真正启动前还要重验到期、当前尝试与受管输入。
3. **调度与退出。** 调度事务占住节点唯一写名额，创建或绑定写尝试、递增该节点写名额的内部代次、写入启动命令。领取启动命令仅表示已派发，实际启动回执才让任务进入执行中。取消排队但已派发的任务须先确认命令未启动或进程已停。成功执行在确认进程停止、证据文件落盘、数据库归档提交后释放名额，并进入 P1 待验收或 P2 待复核。已核实失败或取消时先保存可取得的记录再释放。节点失联保留名额。
4. **复核与返工。** 复核读取不可变版本，可与其他工作区的写执行并行。P2 验收事务必须同时满足当前状态为待验收、版本未变、当前独立复核已通过、必需证据可用。接受记录结论，保留分支和工作区。退回在两轮限额内增加计数、排队并创建新的执行尝试，交付时形成新版本。超限保留主状态并增加等待答复。复核崩溃时核实旧进程已结束后，允许同版创建新的只读尝试。已失败、已取消的任务仅可关联另建。

上述写事务只包含本机数据库操作。模型请求、文件传送、进程操作和 SSE 发送在事务外完成。一次业务变更只增一次任务 `revision`，可同时产生多条全实例事件。心跳或高频输出不应反复作废用户正在审看的决定。

## 4. 至少一次派发与崩溃恢复

控制面可能重复交付同一内部命令。Runner 执行前核对实例绑定、节点、当前尝试、当前连接 `generation`、`leaseId` 和命令所绑定的写名额代次、操作摘要及实际可执行范围。受管测试还核对工作区、输入指纹、允许范围及授权有效期。失去控制服务连接时停止发起需要新授权的动作。写名额的代次校验能拒绝旧所有者的回执或新动作，不能让已经在运行的外部进程停止。三项凭据分别校验。`generation` 随节点新连接换代，阻止旧连接领新工作。`leaseId` 对应某条命令的一次领取，可续期，重新领取沿用 `commandId`。线上的 `fence` 表示写名额所有权的代次，随该节点写尝试换主递增，绑定尝试和受管执行动作，心跳超时或浏览器重连不改变它。换写名额前须核对旧进程。当前连接可补报旧租约的历史观察，不能凭旧租约启动动作。

| 故障窗口 | 可核对的耐久记录 | 重启或重连时的处理 |
| --- | --- | --- |
| 用户请求尚未提交，或已提交但浏览器未收回执 | 控制库的用户命令回执、决定和派发记录处于同一事务 | 已提交则返回既有结果。未提交可按原键处理。设备撤权优先于命中缓存。 |
| 控制服务提交后、Runner 领取前退出 | 控制库保留相同 `commandId` 的待派发项 | 恢复服务后原命令仍可领取。投递器只能重送同一标识，不能创建第二次尝试。 |
| Runner 已领取，在记录“即将启动”前退出 | Runner 排他执行日志能确认从未进入启动窗口 | 当前授权、尝试和代次都有效时可接受同一命令。日志丢失或损坏视为未知。 |
| 写入“即将启动”后，在确证启动或得到结果前崩溃 | 本地记录、启动身份、存活进程、工作区与测试证据 | 可验证原进程仍在则接回观察。原生会话可续接时继续原尝试，仅可读历史时展示可选新尝试。只凭缺少退出记录或旧 PID 不能断言动作未发生。仍不明时停止重发，保留名额并提请所有者核实。 |
| Runner 已持久化结果，但上报中断，或控制面收妥后确认丢失 | 同一 `reportId`、`commandId`、结果摘要及归档内容 | Runner 只重传结果。控制服务按 `reportId` 去重，同标识不同内容隔离并记录异常，不重复改变主状态。 |
| 更换尝试后旧进程发来回执 | 尝试标识、代次、报告标识及产生时间 | 保留原尝试的真实历史。禁止释放新尝试的名额、覆盖新版产物、满足新版复核或撤销已经生效的决定。 |
| 取消与启动交错，或节点长期失联 | 取消意图、命令发放情况、Runner 中的进程组和已停证明 | 停止新派发，向同一尝试发停止意图。能证明尚未启动或已停止才结束任务、释放名额。重新登记 Runner 或心跳超时本身不能解除名额。 |

命令去重仅约束平台记录。对于启动后失去回执的外部副作用，系统没有通用的恰好一次保证。若缺少可验证证据，用户看到最后确认事实、不确定的动作及影响范围。人工处理记录依据，已确认旧执行停止后才能另开尝试。恢复节点也不能重新兑现已过期或已撤销的授权。

## 5. 事件快照、归档和反压

**快照与补读。** 事件序号由事务内的实例计数器连续分配，从 1 起。事务回滚不会消耗序号，裁剪历史不复用序号。控制服务在同一 SQLite 读事务内取得当前视图、`streamId` 和 `highWater`，把只含轻量字段的有序投影暂存为限时的 `snapshotId` 后关闭读事务。后续分页均读取同一份投影，所有页使用相同水位，不跨浏览器请求持有 SQLite 读锁。快照到期后回收投影及分页游标，容量达到上限时优先清理过期快照，对已失效的快照要求整份重取。浏览器装入全部页后从该位置之后订阅全实例 SSE，游标形式为 `streamId:seq`。服务先补读已提交事件再追赶增量，通知只负责唤醒读取，按持久化 `seq` 排序及消重。事件不按任务过滤。游标早于保留窗口、超前或源自其他事件流时要求重新读取快照。慢客户端超过发送缓冲时断开并允许补读，不能把无限缓冲或长读事务留给一个浏览器。

**保留策略。** 同步事件仅用于有限窗口重放，窗口及可读下限由服务保存并报告。初始容量在容量演练后冻结。任务、审计、决定、归档证据及已生效命令的去重材料独立保存。P1/P2 不随事件裁剪删除这些记录。Runner 已确认的完整上报可压缩，但保留命令标识、启动窗口、结果摘要和确认位置，直至该绑定代次被永久退役且不存在未核对动作。诊断用大体积输出可截断，标注范围、原因和原始字节数。不得以截断数据冒充完整证据。

**归档协议。** Runner 提交按版本组织的清单，包含任务、尝试、基准提交、执行输入、证据种类和每个对象的 SHA-256、字节数及媒体类型。控制服务流式写入临时文件，限制字节数，校验摘要与长度，写盘后在同一文件系统原子发布到按摘要寻址的只读路径，并持久化所在目录。只接受服务端分配的路径。文件就绪后，用一个数据库事务发布版本、引用、审计、事件和回执。提交前崩溃只会留下无引用文件。保留宽限期后经引用和活跃归档检查清理，备份期间固定相关对象。重复归档同一操作仅返回既有版本，内容变化必须生成新版。已索引对象若缺失或损坏，标出对象、阻止复核通过和验收，已完成任务保留原决定。只允许哈希匹配的字节修复同一版本。

**受管输入指纹。** 受管测试需冻结本次允许的测试命令、实际参数、工作目录、受控环境配置和待测文件集合。清单按规范化路径排序，记录文件类型、执行位、字节摘要、删除及符号链接目标，并包含会实际读取的未跟踪输入。审批绑定清单指纹，执行从该冻结输入读取，把临时输出写到单独可写目录。无法冻结测试依赖或约束替代执行路径的配置不公开为受管能力。启动时再次比较摘要。测试结果记录指纹、退出码和日志内容。模拟、未运行和 Agent 自述分别标记。

**摘要字段。** 单个清单条目的 `sha256` 是原始文件字节的 SHA-256，以 64 位小写十六进制表示。三个结构化摘要字段在线上统一加 `sha256:` 前缀，后接 64 位小写十六进制。结构化摘要按用途分域，以 `domain`、`formatVersion`、`value` 三字段组成外层对象，分别选用 `input`、`content`、`manifest` 域，格式版本取 1。校验字段后采用 JCS 规范化为 UTF-8 字节，计算 SHA-256 并输出小写十六进制。同一格式固定字段与可空约定，拒绝重复键。集合先按规范定义的唯一键排序，命令参数等有顺序语义的数组维持原序。[RFC 8785](https://www.rfc-editor.org/rfc/rfc8785)

| 字段 | 纳入范围 | 验证位置 |
| --- | --- | --- |
| `inputDigest` | 受管命令、参数、范围、尝试、工作区、环境定义版本及冻结文件指纹。问题答复使用同一输入域的独立类型，摘要覆盖问题和允许答案。 | 发起授权或提问时记入 `frozenInput`。收到决定时核对，受管测试启动前再次验证。 |
| `contentDigest` | 当前交付的基准和内容集合。条目按 `entryId` 排序，纳入标识、证据类型、媒体类型、长度和原始字节摘要。 | 验收、复核及修复归档时确认读取同一内容。它不充当任务版本标识。 |
| `manifestDigest` | 完整上传清单的规范字段，包含基准、尝试关联和有序条目元数据。排除摘要自身、上传进度及临时存储路径。 | 恢复上传及最终归档时核对。相同 `uploadKey` 携不同清单应拒绝。 |

**磁盘和队列反压。** 控制服务与 Runner 分别配置单文件、单次归档、输出缓冲和剩余磁盘阈值，预留关键回执空间。达到高水位时暂停新写任务和大对象接收，展示原因，允许读取历史、处置待办及上报必要回执。Runner 无法持久写入启动记录时不得启动动作。遇真正写满时不确认任何未落盘的决定或报告，停止派发并提示释放空间。残缺归档保留可核查缺口，经恢复后从已确认对象继续上传，原运行不因归档失败再次启动。

## 6. 一致性备份、迁移和恢复

1. **制作备份。** 控制服务临时禁止回收产物，在本地暂存目录生成 SQLite 一致性备份。从完成的备份库读取 `highWater` 和完整引用集，再复制、逐个校验不可变文件。清单记录来源实例、结构和格式版本、快照时间、序号、数据库摘要、对象摘要和长度，以及外部仓库、节点日志和原生会话等未包含项。备份不导出模型或操作系统登录材料、可携式会话或配对秘密。完成全量校验后才发布备份并解锁回收，未完成包显式标为不可恢复。禁止仅复制活动 WAL 模式下的主库文件。[SQLite 在线备份](https://sqlite.org/backup.html)
2. **升级数据格式。** 启动时检查数据库和清单格式。升级先停止新派发，等待在途写工作结清或经所有者确认取消，冻结新决定并保留 Runner 未确认回执，制作可验证备份，再在暂存副本分版本迁移。每步校验外键、行数、唯一决定、活动写名额、当前版本引用与历史证据。可续跑或从原备份重建副本。遇未知新格式、空间不足或校验失败保留当前库和原文件，不切换。升级重开须与 Runner 对账后再派发。回退涉及数据格式时恢复配对的程序版本和迁移前备份，标明回退点后的变更差额。
3. **恢复到干净实例。** 本机管理者核对来源实例及快照时间，在隔离目录验证清单、数据库完整性及外键、对象个数、长度和字节摘要，再演练读取任务、决定与产物。拒绝把其他实例的备份覆盖到活动实例。所有校验通过才在停写状态原子切换完整数据目录，保留先前可用数据。校验失败报告具体对象。校验值证明内容一致性，自托管维护者仍需选择可信备份来源。
4. **失效旧身份与派发。** 在对用户开放前，为恢复实例生成新的 `streamId`、授权世代及 Runner 绑定世代。关闭旧配对、设备会话与授权入口，废止可继续使用的旧授权，按主机管理流程重新绑定设备和 Runner。保留历史有效决定及操作者。原 `highWater` 作为新流起点，旧游标必定重新取快照。旧内部派发冻结，尤其是已批准而结果未知的动作。控制面与重连节点对账原身份、执行日志、进程和工作区，能证实的已有结果仅补记一次。无法查实则保留阻塞和写名额。旧实例须先停用或隔离，防止备用恢复实例与原实例同时指挥同一节点。
5. **验证可用性。** P1 完成单机持久化、重启读回、备份清单及文件校验。P2 把已完成和中断任务实际导入干净实例，覆盖坏包、错实例、缺文件和设备撤销，再验证独立复核证据、未知副作用保护和手机从新流恢复。模型服务掉线时，控制服务仍应能读取已归档资料。
