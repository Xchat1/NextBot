# NextBot 产品体验与操作说明

**v0.1 评审稿 | 2026-11-27**

本文描述首发版计划提供的操作体验，供产品、设计和自托管用户一起评审。产品定位与阶段取舍见 [产品需求文档](01-prd.md)，命令、状态转换与异常处理见 [功能规格](03-functional-spec.md)。

## 1. 谁在使用 NextBot

| 使用身份 | 典型问题 | 主要操作 |
| --- | --- | --- |
| 项目操作者 | 我交办了什么，谁在处理，产物能否接收？ | 在电脑创建任务，在手机答复或授权，检查改动与复核意见，决定接受或返工。 |
| 自托管维护者 | 主机为什么接不到任务，我的设备和凭据还安全吗？ | 配置私网访问、执行节点、工作区和 Agent，撤销设备访问，处理重启和恢复。 |

首发由同一个人承担这两种身份，可以使用多台设备。电脑适合编辑长任务说明和查看完整差异，手机适合处理待办、查阅复核摘要及作出决定。任务归属自托管实例，关闭浏览器后可从另一台已授权设备继续查看。

| 规划阶段 | 用户可评审的体验 |
| --- | --- |
| P1 基础验证 | 单用户、单执行节点、Codex，经私网 HTTPS 进入响应式 Web。验证电脑派发、手机接手、断线补看、人工验收。控制服务和执行节点可在同一台主机部署。 |
| P2 可选复核 | 在同一节点可增加 Claude Code，由 Codex 执行、Claude Code 只读复核。通过验证的反向组合也可启用。支持从复核意见回到对应产物版本，要求返工并重新验收。 |
| P3 后续 | 再评估多节点、跨机委派等体验。首发界面围绕一个节点组织，用户无需做跨机调度决策。 |

## 2. 打开产品后看什么

| 入口 | 屏幕上先回答的问题 | 主要内容 |
| --- | --- | --- |
| 任务 | 哪些任务需要我处理？ | 优先看到待我处理的授权、答复和验收，其余任务按最近活动排列。每项显示任务名、主状态、阻塞原因和最近更新时间。 |
| 新建任务 | 我要在哪个项目完成什么，怎样算完成？ | 工作区、目标、验收条件和执行方式。提交前展示实际节点、Agent 角色与能力。 |
| 任务详情 | 当前做到哪一步，接下来该谁操作？ | 顶部显示主状态、当前产物版本及下一步动作。下方依次提供时间线、产物与差异、复核记录和历史尝试。 |
| 设置 | 这台主机和我的设备是否就绪？ | 节点连接、工作区范围、Agent 可用性、已授权设备和运行诊断。 |

电脑可并排展示任务列表、详情与差异。手机先显示任务详情，再逐项展开差异和事件记录。两种布局沿用相同的任务名称、状态、产物版本和按钮用语，从手机切回电脑可以直接找到刚处理的决定。

## 3. 第一次使用

1. **维护者准备主机。** 通过自己的私网 HTTPS 地址进入实例，检查节点在线，选定允许执行任务的工作区。界面应能区分“节点失联”“工作区不可写”“Agent 尚未就绪”，并指出需要在主机上处理的项目。
2. **检查 Agent。** P1 检查 Codex。P2 另检查 Claude Code 及其只读执行环境。可执行文件、登录态、执行能力与只读约束分别展示。只能确认命令已安装时，标记其余能力为“待验证”。
3. **接入手机。** 在同一私网或已接通的 VPN 上，从手机打开实例的 HTTPS 地址，完成设备授权。电脑端“已授权设备”应能识别这部手机，并能撤销其访问。手机端无需配置模型密钥。
4. **检查任务入口。** 在两端打开同一个任务列表。空列表给出“新建任务”入口，主机未就绪时显示具体原因。首次验证可选一个能复现的问题，例如报告导出时遇到空数据便失败，并准备一个小样本。

## 4. 从电脑派发，到手机决定

以下示例包含配置了独立复核的 P2 路径。首发的 Codex 任务可直接进入人工验收。

### 4.1 电脑上创建任务

在“新建任务”选择项目工作区，填入目标和可核对的验收条件。对代码任务，界面应显示本次工作区和起始版本，方便用户识别改动基线。任务说明可保存为草稿。提交后，详情页用同一任务编号跟踪执行、复核和验收。

| 示例字段 | 示例输入或显示 |
| --- | --- |
| 任务 | 修复报告导出失败 |
| 工作区 | 示例服务 / 报告导出模块 |
| 目标 | 修复报告在输入为空时导出失败的问题，保留现有导出格式。 |
| 验收条件 | 提供失败输入的回归测试记录，用已有样本核对导出格式。 |
| 执行与复核 | Codex 执行，Claude Code 在可强制只读的环境内复核。 |
| 提交 | 创建并排队 |

排队成功后关闭网页，节点仍可继续已领取的任务。在手机打开同一任务，应能看见当前步骤、节点最近联系时间和新产生的事件。

### 4.2 手机上处理执行中的请求

任务卡把主状态和需要人介入的原因分别显示，例如“执行中 · 等待授权”。进入详情即可了解是谁提出请求、要做什么、作用于哪个工作区、有效期和当前尝试。手机上有两种不同的输入方式。

| 系统在等什么 | 用户看到什么 | 如何处理 |
| --- | --- | --- |
| 等待答复 | 具体问题，以及此前已经给出的要求。 | 输入补充信息并发送。答复记入当前任务时间线。 |
| 等待授权 | 一项受管动作、目标、范围、发起者和有效期。 | 选择“允许本次”或“拒绝”。拒绝或过期后该项动作默认不执行。 |

动作管控以当前适配器和节点实际能约束的范围为准。详情页应显示能力边界。两个设备同时打开同一请求时，后提交的设备应看到已经处理的结果和时间，避免使用过期按钮重复授权。

例如，维护者预先登记了导出回归测试命令。执行者请求运行时，手机上展示确切的工作区、版本、命令和参数。点“允许本次”后，可在时间线查看节点报告的启动与运行结果。拒绝或超时会关闭这项授权，执行者可按允许范围改用其他步骤，确需该命令时再说明原因并重新申请。

### 4.3 手机上读复核结果

执行者提交产物后，任务进入“待复核”。只读环境验证通过并启动复核后，状态变为“复核中”。复核者引用本次产物版本，检查验收条件并留下意见。若节点无法强制只读，页面显示缺失条件与可行的修复入口，系统不得静默改用可写复核。P1 的单 Agent 流程由操作者直接检查产物并验收。

示例中，v1 只附了普通输入的测试记录。Claude Code 复核时发现缺少空数据证据，将 v1 退回并附上理由。手机可查看这条意见，此时没有可接受的版本。第二次执行补充空数据用例并归档运行记录，生成 v2。Claude Code 核对 v2 的差异、回归测试及格式比对记录，通过后才出现以下待验收页。

```text
修复报告导出失败                      待验收
当前产物 v2                       执行尝试 2

本次改动
导出逻辑和回归测试                   查看差异

Claude Code 的复核结论          通过 · 对应 v2
空数据回归测试通过。既有样本的导出格式一致。
查看本次测试记录               查看格式比对记录

[要求返工]                         [接受 v2]
```

点击“查看差异”核对实际改动，点击“查看本次测试记录”核对执行者运行的用例、结果和对应版本。检查项若只有 Agent 的文字描述，应标注“仅有自述”。缺少运行记录时显示“无运行证据”。P2 只将已通过独立复核的当前版本交给操作者验收。

### 4.4 验收、返工和交付

- **接受当前版本。** 在详情页核对版本及验收条件后点击“接受 v2”。服务端确认 v2 仍是当前版本，再记录决定并将任务置为“已完成”。验收记录可回看，合并与推送保留为用户另行决定的操作。
- **要求返工。** 即使 v2 已通过复核，操作者若发现样本遗漏了原有日期列，也可说明原因，要求补充比对。每次返工会创建新的执行尝试并在交付时生成新的产物版本，旧版本和意见可继续查阅。复核退回与用户退回共用两轮返工额度。若第三次提出返工，界面显示已达上限，提供“另建关联任务”或“结束本任务”。已通过复核且仍可验收的当前版本也可由用户接受。
- **处理过期页面。** 若电脑正显示可验收的 v2，同时手机已要求返工，电脑再次点击“接受 v2”时应提示任务已更新，并提供“查看当前尝试”。用户只可接受当前可验收的版本。
- **检查交付。** 从历史记录可定位本次工作区、起始版本、产物、复核结论与验收人。用户随后可进入自己的代码审阅和交付流程。

## 5. 读懂状态与异常

| 任务主状态 | 界面应说明什么 |
| --- | --- |
| 草稿 | 任务尚未提交，用户可继续编辑。 |
| 排队中 | 任务已受理，正在等待节点领取或可用执行资源。 |
| 执行中 | 当前执行者、执行尝试和最近进展。 |
| 待复核 | 当前产物已记录，正在等待复核。 |
| 复核中 | 复核者正在查看的产物版本。 |
| 待验收 | 当前版本、复核意见或直接验收依据，以及接受、返工入口。 |
| 已完成 | 被接受的版本和决定时间。 |
| 已失败 | 出错的步骤、保留的产物、可用的恢复动作。 |
| 已取消 | 取消记录和已留下的改动，方便用户检查工作区。 |

“等待授权”“等待答复”“节点失联”显示为阻塞原因，并列出任务最后确认的主状态。客户端断网应单独展示连接提示，手机离线本身无法证明节点失联。

| 遇到的情况 | 用户操作与界面反馈 |
| --- | --- |
| 手机锁屏后重新打开 | 显示正在同步，按记录位置补齐历史。补齐后显示最新状态、尚待处理的决定与结果，避免重复显示同一事件。 |
| 主机重启或节点失联 | 维护者先检查主机与节点服务。页面保留最后一次确认的状态和时间，重连后核对当前尝试。结果未核实时提示“上次执行结果待确认”，保留产物供检查。 |
| 提交授权或验收后连接中断 | 回到任务查看决定记录与当前版本。界面应先查询提交结果，再显示可用操作，防止重复执行。 |
| 执行失败，需要重试 | 如果原进程仍在且适配器支持，可重新挂接。原进程已结束且可续接原生会话时，界面显示支持的续接方式。同任务重试仅对非终态提供，须先核实前次进程与已发生的副作用，再由用户发起新尝试。任务已经进入“已失败”或“已取消”时，重做只能创建关联原任务的新任务。 |
| 希望停止任务 | 发起取消后查看处理进度，服务确认后显示“已取消”。界面提醒“已写入的文件会保留”，并提供查看改动的入口。 |
| 更换或丢失设备 | 仍有可信设备时，从“设置 → 已授权设备”撤销旧设备，再为新设备配对。若所有已配对设备均不可用，登录主机管理环境，使用“设备访问恢复”重置所有者设备凭据、撤销旧会话并重新配对。在新设备打开原任务查看进度。 |

## 6. 自托管维护者日常检查

首发设置页应按故障所在位置给出线索。优先展示可操作的状态，日志详情作为进一步诊断的入口。

| 检查点 | 页面应能回答的问题 |
| --- | --- |
| 控制服务与节点 | 控制服务是否可访问？节点最后一次联系是什么时候？正在处理哪个任务和尝试？ |
| 工作区与产物 | 节点能否读取选定项目、创建本次工作的目录、持久保存结果？任务所属目录与产物版本在哪里？ |
| Agent 能力 | 哪个 Agent 已配置，哪项能力已经验证？授权、恢复或只读约束缺失时，具体影响哪个操作？ |
| 设备与访问 | 哪些设备获得过授权？当前设备是哪台？撤销指定设备后，其他设备是否还能继续访问？ |
| 备份与恢复 | 服务备份包含哪些任务记录、归档产物、授权与审计记录？节点工作目录和模型凭据需要单独安排保存。恢复后按任务抽查产物、复核与决定记录的对应关系，对中断执行逐项确认后再决定是否重试。 |

主机上存放的模型凭据由维护者管理。使用远程模型时，模型服务会按所选 Agent 的配置接收相关输入。设置页应让维护者看清凭据在哪台主机使用、工作区开放到哪里，以及浏览器能看到哪些数据。

## 7. 界面评审清单

- 操作者可用键盘完成创建任务、查看差异、授权和验收。焦点顺序与页面阅读顺序一致，弹窗关闭后焦点回到原操作位置。
- 内容在手机窄屏放大后仍可阅读。路径或长行差异支持独立展开，按钮具有足够的触控面积。状态采用文字与图标共同表达。
- 新输出到达时保留用户正在查看的位置和输入草稿。屏幕阅读器优先播报授权、完成、失败等需要关注的变化，避免逐字播报流式输出。
- 设备名称、节点名称和时间线可帮助追溯决定。NextBot 的配对页面和诊断导出应对配对凭据及已知敏感字段做遮盖。分享 Agent 的自由文本输出前可先预览内容。若后续增加系统通知，锁屏预览仅提示“有任务待处理”。
- 评审者应可用同一示例走完电脑派发、手机断线重连、版本返工及跨设备拒绝过期验收。每一步都应能答清“谁在做、针对哪一版、还需要我做什么”。
